# excel-plugin — Market Pulse (learning project)

A deliberately small **Excel task-pane add-in** built with TypeScript and the
Office JS API. It exists to learn the platform's core patterns by doing:

- **Insert sample data** — writes a small table starting at the selected cell
  using `Excel.run` with **one batched `context.sync()`**.
- **Live updates** — a 2-second timer random-walks the prices and writes the
  whole block back per tick (throttled, batched — never one API call per cell),
  with per-tick error handling so a bad tick doesn't kill the stream.

## Run it (Mac)

Prereqs: Node.js, Excel for Mac.

```bash
npm install
npm start        # sideloads the manifest into Excel's add-in folder, then
                 # starts the HTTPS dev server on port 3000
```

Then in Excel: open a workbook, go to **Insert -> Add-ins**, and pick
**Market Pulse** (it appears under the developer/sideloaded add-ins). The
ribbon also gets a **Market Pulse** group on the Home tab.

The dev server serves over HTTPS using a local certificate generated by
office-addin-dev-certs into `~/.office-addin-dev-certs`. If Excel refuses to
load the pane, trust that CA once (Keychain Access -> the "Developer CA for
Microsoft Office Add-ins" cert -> Always Trust).

Stop the dev server with Ctrl+C. Re-run `npm run sideload` only if the
manifest changes.

Pieces, if you want them separately: `npm run dev-server` (server only),
`npm run sideload` (copies `manifest.xml` into
`~/Library/Containers/com.microsoft.Excel/Data/Documents/wef/`).

## Dependency hygiene

`npm audit` reports **0 vulnerabilities**, deliberately:

- All direct dev dependencies are pinned to current major versions.
- The usual `office-addin-debugging` package is **not** used: under the hood
  it bundles the entire Microsoft 365 Agents Toolkit CLI, which drags in an
  Azure auth library (`@azure/msal-node`) and several old `adm-zip` copies
  with open high-severity advisories — a lot of attack surface for a tool
  whose only job here is copying a manifest and opening Excel. Sideloading
  on Mac is just a file copy into Excel's `wef` folder, so `npm run sideload`
  does exactly that and nothing more.
- TypeScript is held at 5.x (not 7.x) because ts-loader does not yet support
  the TypeScript 7 compiler API.

## Layout

- `manifest.xml` — the add-in manifest (identity, permissions, ribbon button)
- `src/taskpane/` — task pane UI + logic (`taskpane.ts` is the interesting file)
- `src/commands/` — FunctionFile required by the manifest (currently a stub)

## Concepts this exercises

- Host-bridged API: web code talks to Excel through a request context, not directly
- Batching + `context.sync()` round-trips (the #1 performance lever in Office JS)
- Requirement sets / capability detection across Excel on Mac, Windows, and web
- Sideloading, manifests, and local HTTPS dev certs — the deployment basics
